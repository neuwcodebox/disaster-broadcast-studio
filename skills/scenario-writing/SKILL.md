# 재난방송 호러 작품 작성

## 역할과 작업 위치

이 스킬은 엔진 개발 AI와 별개의 창작 AI가 사용한다. 사용자는 npm CLI를 설치하고 `dbs init <작품 폴더>`로 독립 작업공간을 만든다. 이 스킬은 사용자 범위에 한 번 설치해 여러 작품에서 사용한다. [설치·갱신 안내](https://github.com/neuwcodebox/disaster-broadcast-studio/blob/main/skills/README.md)의 GitHub 설치 또는 주소 직접 읽기 방식을 사용할 수 있다. 엔진 개발 저장소나 개발용 AGENTS.md는 필요하지 않다.

실제 작품은 사용자가 지정한 창작 워크스페이스에 작성한다. 스킬 배포물 내부에 작품을 저장하거나 엔진 코드에 줄거리·문안을 넣지 않는다. 기술 검증용 데이터와 실제 작품은 구별한다.

작품에서 참조할 음원과 합성 기록은 `audio/`, 음원 생성 코드는 `audio-code/`에 둔다. 렌더링한 전체·구간 영상, 프레임 이미지, 검토 자료, 게시용 출처 등 산출물은 `init`이 만드는 `output/`에 모은다. 작품 폴더에서 명령을 실행하며 `--out output/...`으로 경로를 지정한다. 결과의 부속 `.json`·`.credits.txt`는 결과 파일 옆에 보존한다.

## 근거 찾기

[창작 근거 자료](references/README.md)에서 필요한 종류를 선택한다. 모든 자료를 무조건 읽기보다 장면에 필요한 발령 체계·기관·문안을 찾아 원천 근거까지 확인한다.

- [재난문자 운영·발송 기준](references/disaster-sms-rules.md): 사용기관·직접 발송 권한, 기관별 표준문안 위치, 최신 호우·지진 문자 기준과 실종경보 구분.
- [표준문안 전문](references/disaster-sms-templates.md): 해당 재난 유형과 행동 단계에 맞는 실제 문장.
- [실제 발송 문자 사례](references/alert-examples.md): 예방·통제·대피·초동과 후속·복구·해제·훈련 등 실제 문안과 기록 시각·출처.
- [민방위 경보](references/civil-defense.md): 발령·전달, 사이렌·방송·자막·문자 사이의 차이.
- [기상·지진·홍수·산사태 정보](references/hazard-information.md): 시간·단계·관측값의 의미.
- [상황 지표](references/status-systems.md): 상태바에 사용할 실재하는 공식 체계의 명칭·단계·적용 범위와 공개 근거.
- [재난 대응 조직과 권한](references/response-system.md): 중대본·중수본·지대본·현장 지휘의 역할, 상황보고·매뉴얼, 대피·통제·재난사태와 특별재난지역.
- [현장·생활기반 대응](references/field-and-infrastructure-response.md): 침수·산불·화재·붕괴와 정전·통신·급수 장애에서 구조·통제·대피·차단·복구가 진행되는 방식.
- [보건·유해물질 대응](references/health-and-hazard-response.md): 원인불명 집단발병의 조사, 화학사고·방사선비상의 확인기관과 주민 보호조치.
- [전쟁·통합방위·국가긴급권](references/war-and-emergency-system.md): 군·경·행정의 역할, 비상대비·동원·징발, 전쟁·계엄·긴급명령의 각각의 요건과 통제.
- [화생방·테러 대응](references/cbrn-and-terror-response.md): 적의 공격·테러와 평시 사고의 구별, 탐지·평가·현장 대응·주민 보호와 경보 전달.
- [뉴스 표현](references/news-writing.md): 발표 주체, 확인된 사실, 후속 갱신의 문체.
- [실제 헤드라인 사례](references/headline-examples.md): 재난·생활기반 장애·군사 관련 보도의 실제 제목과 날짜·매체·정보 선택 방식.

공식 표준문안, 실제 발송·보도 사례, 새 창작 문장을 구별한다. 원문 사례나 사용자 예시를 의무적인 플롯으로 삼지 않는다. 자료의 판본보다 과거를 배경으로 하면 해당 시기의 제도를 확인하고, 확인되지 않은 사실을 실제 규정이라고 쓰지 않는다.

## 집필과 연출

현황판은 공개된 재난문자와 뉴스를 모아 라이브 스트리밍하는 서비스다. 각 요소는 그 작성 주체가 당시 알 수 있는 정보, 처한 환경, 권한·책임, 전달 목적과 수신자를 기준으로 쓴다. 작가가 아는 사건의 전모가 기관·기자·운영자·채팅 참여자 모두에게 주어진 것은 아니다.

재난문자는 발송기관이 위험과 필요한 조치를 판단해 국민·주민에게 알리는 공적 안내다. 기관의 책임과 발송 목적에 맞춰 대상자에게 필요한 내용을 선별한다. 뉴스는 기자가 취재·확인한 범위에서 절제해 보도하며 속보·후속 보도·현장 연결의 성격을 구별한다. 즉각적인 반응과 일상적 중계는 주로 채팅이 맡는다. 현황판의 표시와 방송 안내는 서비스 운영자가 공개 정보와 송출 상태를 전달할 수 있는 범위에 둔다.

상태바에는 작품의 배경시대에 실재하는 공식 체계의 단계·발령 상태만 표시한다. 공식 자료에서 체계의 명칭·단계·발령 주체·적용 범위를 확인하고, 작품 안에서 공개된 정보에 따라 갱신한다. 일반적인 상황 요약이나 개별 대응 조치는 뉴스 등 목적에 맞는 매체로 전달하며, 임의의 체계·단계·상태명을 만들지 않는다. 근거를 확인하지 못한 항목은 표시에서 제외한다.

화면과 소리는 영상을 보는 시청자의 관점에서도 성립해야 한다. 정보와 소리가 어떤 경로로 방송에 들어왔으며 시청자가 누구의 경험이나 어떤 상황으로 받아들일지 판단한다. 연출 의도와 실제로 전달되는 의미가 맞아야 한다. 세부 판단 기준은 [방송으로 보여주는 연출](references/direction.md), 음향의 적용은 [음원 제작](references/audio.md)을 따른다.

1. 사용자가 정한 소재·길이·분위기·매체를 바탕으로 사건의 흐름을 설계한다. 미정인 창작 선택은 작품에 맞춰 결정하되 이미 합의한 조건을 바꾸지 않는다.
2. 사건 내용과 각 주체가 정보를 얻고 전달하는 과정을 설계한다. [대응 조직과 권한](references/response-system.md) 및 해당 사건의 참고자료에서 중앙부처·지자체·현장기관·시설 운영자가 맡는 조치를 확인한다. 법령의 권한·매뉴얼의 절차·실제 대응 사례를 구별하며, 기관별 현장조치와 보고·발표가 병행되는 흐름을 구성한다. 사건 발생·상황 파악·판단·발령·취재·보도·수신 시각이 다르면 그 차이를 반영한다. 모든 과정을 화면에 설명할 필요는 없지만 전달 시점과 내용에는 근거가 있어야 한다.
3. 문자의 대상·행동·발신자와 뉴스의 발표 주체·확인 범위를 구별한다. 발신기관과 발송 대상을 혼동하지 않으며, 모든 문자에서 본문·지역 코드·지도 범위를 맞춘다. 도 전역이면 소속 시군 전체를 조회한다. 수신 시 채우기가 부드럽게 나타났다 사라지는 지도 강조는 기본 기능이며 필요하면 끈다.
4. 상태·방송 안내·등급별 문자 알림음은 엔진 기본 기능을 쓰며 작품별로 중복 제작하지 않는다. 뉴스는 기본 무음으로 두고 필요한 경우에만 소리를 명시한다. 이벤트의 `sound`로 끄거나 교체한다. [Tone.js 음원 제작](references/audio.md)의 실행 가능한 예제를 활용해 필요한 소리를 만든다. 기존 로컬 음원도 사용할 수 있으며 출처·사용권을 기록한다.
5. 내용과 함께 등장·퇴장·지도 이동·강조·음향·침묵·전환의 시점을 작성한다. 컷 내부 시간은 현실과 1:1로 흐르게 하고, 시간 생략은 명시적 컷 경계의 `clockTransition`으로 표현한다. 최초 오프닝이 끝난 뒤와 컷 전환 뒤에는 기존 화면을 읽고 상황을 파악할 여유를 둔 다음 새 요소를 등장시키는 것을 권장한다. 시계 전환이 있으면 강조·숫자 이동·도착 시각 유지가 끝난 뒤에도 호흡을 둔다. 특히 도입부에는 주제 사건과 무관한 평범한 뉴스·안전안내 문자·일상 채팅으로 평소 방송의 흐름을 보여주는 것을 권장한다. 구체적인 배치와 간격은 [방송 연출의 호흡과 변화](references/direction.md#호흡과-변화)를 따른다.
6. 절제된 방송 화면을 기본으로 삼되 모든 작품에 같은 긴장 장치나 반전을 강제하지 않는다. 행정 표현의 현실감과 읽을 시간을 확보한다.

## 엔진을 이용한 확인

[작품 파일과 CLI](references/format.md)에 따라 외부 작품 파일을 작성한다. 정확한 필드 계약은 설치된 CLI의 `dbs schema`, 명령은 `dbs --help`로 확인한다.

`dbs validate` → `dbs preview`로 화면·음향 재생과 탐색 → 문안 가독성·지도 범위·음향·시간 수정 → 필요한 `dbs frame`·구간 `dbs render` 검증 → 전체 `dbs render` 순으로 진행한다. 웹 미리보기는 저장한 변경을 현재 위치에서 일시정지해 반영한다. 중요 장면의 앞뒤 프레임과 컷 경계를 확인하며 매번 전체 영상을 다시 출력하지 않는다. 작품 데이터에서 고칠 수 있는 오류는 그곳에서 고치고, 엔진 기능이 부족하면 필요한 기능을 구체적으로 분리한다. 창작 중 엔진 코드를 임의로 바꾸지 않는다.

## 결과물 확인

- 전달 묶음은 시나리오·필수 자산·재생성 코드·출처 안내로 구성하고 임시 검토·통계 파일은 제외한다.

- 내용·시점·공간·기관의 관계가 의도와 일치하는지 확인한다. 의도된 허구 속 모순을 실수로 없애거나, 조사 실수를 의도된 모순으로 포장하지 않는다.
- 각 문장·표시·소리가 해당 주체의 정보·입장·목적과 전달 경로에 맞고, 시청자가 그 출처와 의미를 이해할 수 있는지 확인한다. 문자가 상황 중계로, 뉴스가 채팅 반응으로, 현황판이 비공개 관제 화면으로 변하지 않았는지 본다.
- 실제 규정의 문안과 작품에서 새로 작성한 내용이 참고자료에서 뒤섞이지 않게 한다.
- 출력 파일의 실제 상태와 미검증 항목을 구분해 전달한다. 영상에는 허구임을 알리는 표기를 포함하고, 출력과 함께 생성한 `.credits.txt`의 출처를 게시 설명에 포함한다. 실제 송출이나 외부 게시·업로드는 별도 요청 없이 수행하지 않는다.
