# 재난방송 호러 작품 작성

## 역할과 작업 위치

이 스킬은 엔진 개발 AI와 별개의 창작 AI가 사용한다. 사용자는 npm CLI를 설치하고 `dbs init <작품 폴더>`로 독립 작업공간을 만든다. 이 스킬은 사용자 범위에 한 번 설치해 여러 작품에서 사용한다. [설치·갱신 안내](https://github.com/neuwcodebox/disaster-broadcast-studio/blob/main/skills/README.md)의 GitHub 설치 또는 주소 직접 읽기 방식을 사용할 수 있다. 엔진 개발 저장소나 개발용 AGENTS.md는 필요하지 않다.

실제 작품은 사용자가 지정한 창작 워크스페이스에 작성한다. 스킬 배포물 내부에 작품을 저장하거나 엔진 코드에 줄거리·문안을 넣지 않는다. 기술 검증용 데이터와 실제 작품은 구별한다.

## 근거 찾기

[창작 근거 자료](references/README.md)에서 필요한 종류를 선택한다. 모든 자료를 무조건 읽기보다 장면에 필요한 발령 체계·기관·문안을 찾아 원천 근거까지 확인한다.

- [재난문자 운영·발송 기준](references/disaster-sms-rules.md): 사용기관·직접 발송 권한, 기관별 표준문안 위치, 최신 호우·지진 문자 기준과 실종경보 구분.
- [표준문안 전문](references/disaster-sms-templates.md): 해당 재난 유형과 행동 단계에 맞는 실제 문장.
- [민방위 경보](references/civil-defense.md): 발령·전달, 사이렌·방송·자막·문자 사이의 차이.
- [기상·지진·홍수·산사태 정보](references/hazard-information.md): 시간·단계·관측값의 의미.
- [상황 지표](references/status-systems.md): 위기경보·소방동원령·경찰 비상근무·군 대비태세의 차이와 공개 근거.
- [뉴스 표현](references/news-writing.md): 발표 주체, 확인된 사실, 후속 갱신의 문체.

공식 문안과 새 창작 문장을 구별한다. 원문 사례나 사용자 예시를 의무적인 플롯으로 삼지 않는다. 자료의 판본보다 과거를 배경으로 하면 해당 시기의 제도를 확인하고, 확인되지 않은 사실을 실제 규정이라고 쓰지 않는다.

## 집필과 연출

[방송으로 보여주는 연출](references/direction.md)을 참고해 사건과 정보의 시간차, 읽을 호흡, 매체별 역할을 맞춘다.

1. 사용자가 정한 소재·길이·분위기·매체를 바탕으로 사건의 흐름을 설계한다. 미정인 창작 선택은 작품에 맞춰 결정하되 이미 합의한 조건을 바꾸지 않는다.
2. 사건 내용과 관객이 정보를 보게 되는 시점을 구분한다. 사건 발생·발령·보도·수신 시각이 다르면 그 차이를 명시한다.
3. 문자의 대상·행동·발신자와 뉴스의 발표 주체·확인 범위를 구별한다. 발신기관과 발송 대상을 혼동하지 않으며, 모든 문자에서 본문·지역 코드·지도 범위를 맞춘다. 도 전역이면 소속 시군 전체를 조회한다. 수신 시 채우기가 부드럽게 나타났다 사라지는 지도 강조는 기본 기능이며 필요하면 끈다.
4. 상태·뉴스·방송 안내·등급별 문자 알림음은 엔진 기본 기능을 쓰며 작품별로 중복 제작하지 않는다. 이벤트의 `sound`로 끄거나 교체한다. [Tone.js 음원 제작](references/audio.md)의 실행 가능한 예제를 활용해 필요한 소리를 만든다. 기존 로컬 음원도 사용할 수 있으며 출처·사용권을 기록한다.
5. 내용과 함께 등장·퇴장·지도 이동·강조·음향·침묵·전환의 시점을 작성한다. 컷 내부 시간은 현실과 1:1로 흐르게 하고, 시간 생략은 명시적 컷 경계의 `clockTransition`으로 표현한다. 기존 상단 시계의 강조·숫자 이동·도착 시각 유지가 읽힌 뒤 새 정보를 배치한다.
6. 절제된 방송 화면을 기본으로 삼되 모든 작품에 같은 긴장 장치나 반전을 강제하지 않는다. 행정 표현의 현실감과 읽을 시간을 확보한다.

## 엔진을 이용한 확인

[작품 파일과 CLI](references/format.md)에 따라 외부 작품 파일을 작성한다. 정확한 필드 계약은 설치된 CLI의 `dbs schema`, 명령은 `dbs --help`로 확인한다.

`dbs validate` → `dbs frame`과 구간 `dbs render` → 문안 가독성·지도 범위·음향·시간 수정 → 전체 `dbs render` 순으로 진행한다. 중요 장면의 앞뒤 프레임과 컷 경계를 확인하며 매번 전체 영상을 다시 출력하지 않는다. 작품 데이터에서 고칠 수 있는 오류는 그곳에서 고치고, 엔진 기능이 부족하면 필요한 기능을 구체적으로 분리한다. 창작 중 엔진 코드를 임의로 바꾸지 않는다.

## 결과물 확인

- 전달 묶음은 시나리오·필수 자산·재생성 코드·출처 안내로 구성하고 임시 검토·통계 파일은 제외한다.

- 내용·시점·공간·기관의 관계가 의도와 일치하는지 확인한다. 의도된 허구 속 모순을 실수로 없애거나, 조사 실수를 의도된 모순으로 포장하지 않는다.
- 실제 규정의 문안과 작품에서 새로 작성한 내용이 참고자료에서 뒤섞이지 않게 한다.
- 출력 파일의 실제 상태와 미검증 항목을 구분해 전달한다. 영상에는 허구임을 알리는 표기를 포함하고, 출력과 함께 생성한 `.credits.txt`의 출처를 게시 설명에 포함한다. 실제 송출이나 외부 게시·업로드는 별도 요청 없이 수행하지 않는다.
