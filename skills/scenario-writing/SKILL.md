# 재난방송 호러 작품 작성

## 작업 범위와 작업공간

이 스킬은 엔진 개발 AI와 별개의 창작 AI가 사용한다. 사용자가 정한 소재·길이·분위기·매체를 바탕으로 사건과 방송 연출을 만들고, 요청한 단계까지 완성한다. 텍스트 초안·장면 검토 요청은 그 범위까지 작성하고, 영상 제작 요청은 작품 파일 작성·검증·출력까지 진행한다. 미정인 창작 선택은 작품에 맞춰 결정하되 이미 합의한 조건을 유지한다.

작품은 사용자가 지정한 독립 작업공간에 작성한다. npm CLI 설치와 `dbs init` 초기화는 [작품 파일과 CLI](references/format.md#독립-작업-공간), 스킬의 사용자 공통 설치·갱신은 [설치 안내](https://github.com/neuwcodebox/disaster-broadcast-studio/blob/main/skills/README.md)를 따른다. 엔진 개발 저장소나 개발용 AGENTS.md 없이 사용할 수 있다. 엔진 기능이 부족하면 필요한 기능을 구체적으로 정리해 전달하고, 창작 중 엔진 코드를 임의로 바꾸지 않는다.

집필 기록·생성 코드·원본 자산은 작품의 `src/`에, 재생성 가능한 음원·지도·영상·출력 검토 자료는 `output/`에 둔다. 줄거리와 롤플레잉 기록은 `src/writing/`에 보존하고 Git으로 추적한다. 폴더별 용도와 출력 경로는 [작업공간 구성](references/format.md#원본과-생성-결과)을 따른다. 실제 작품을 스킬 배포물이나 엔진 코드에 저장하지 않는다.

## 집필의 관점

현황판은 공개된 재난문자와 뉴스를 모아 라이브 스트리밍하는 서비스다. 기관·기자·운영자·채팅 참여자는 각자의 환경과 경로에서 얻은 정보로 판단한다. 문안은 그 주체의 권한·책임, 전달 목적과 수신자에 맞춰 쓴다. 작가가 아는 사건의 전모와 각 주체가 당시 알 수 있는 사실을 구별한다.

재난문자는 발송기관이 대상 국민·주민에게 위험과 필요한 행동을 알리는 공적 안내다. 뉴스는 취재·확인한 범위에서 절제해 보도하고, 채팅은 개인의 질문·목격·일상적 반응을 담는다. 지도·상태·방송 안내는 운영자가 수신한 공개 정보와 서비스의 송출 상태를 전달한다. 상태바에는 배경시대에 실재하는 공식 체계의 단계·발령 상태만 사용하며, 그 근거와 작품 안의 공개 여부를 확인한다.

화면과 소리는 영상을 보는 시청자의 자리에서도 성립해야 한다. 정보와 소리가 어떤 경로로 방송에 들어왔으며 시청자가 누구의 경험으로 받아들일지 맞춘다. 매체별 표현과 시간·가독성의 판단은 [방송 연출](references/direction.md)을 따른다. 절제된 방송 화면과 읽을 시간을 기본으로 삼되, 긴장 장치나 반전을 모든 작품에 같은 방식으로 적용하지 않는다.

## 사건 설계와 롤플레잉 집필

먼저 사건의 큰 흐름과 등장 주체를 정하고, [참고자료 안내](references/README.md)에서 필요한 제도·기관·문안을 찾는다. 법령이 정한 권한, 매뉴얼의 절차, 개별 사건의 대응 사례를 구별해 현장조치와 보고·발표가 병행되는 흐름을 설계한다. 사건 발생·관측·보고·판단·발령·취재·보도·수신의 시각 차이를 반영한다.

공식 표준문안, 실제 발송·보도 사례, 새 창작 문장을 구별한다. 배경시대가 자료의 판본과 다르거나 장면의 핵심 판단이 확인 범위를 벗어나면 해당 시기의 원천 근거를 확인한다. 원문 사례나 사용자 예시를 의무적인 플롯으로 삼거나, 미확인 내용을 실제 규정으로 쓰지 않는다.

새 작품이나 여러 주체가 상호작용하는 장면에는 [역할별 반복 롤플레잉](references/roleplaying.md)을 우선 활용한다. 작가가 상황을 조금씩 진행하며 역할 에이전트에 접근 가능한 새 정보만 전달하고, 같은 역할들의 판단·행동·발언을 여러 차례 이어 받는다. 응답의 결과와 공개 여부를 확정해 다음 상황과 다른 역할의 입력으로 연결하면서 시나리오를 써 나간다.

역할의 제안·추측과 확정된 사건·공개 정보를 구별하고, 이전 판단·행동·발언이 이어지도록 기록을 유지한다. 중요한 전개를 수정할 때는 영향을 받는 역할의 기억과 후속 반응도 그 시점에서 다시 진행한다. 작은 문안 수정이나 확정된 장면의 데이터 변환은 작가가 직접 처리할 수 있다.

## 방송 연출과 자산 제작

확정된 사건 중 방송에 전달되는 부분을 문자·뉴스·채팅·지도·상태·방송 안내로 구성하고, 등장·퇴장·이동·강조·음향·침묵의 시점을 함께 정한다. 문자의 본문 대상·지역 코드·지도 범위를 맞추며, 발신기관과 발송 대상을 구별한다. 공식 상태 체계의 확인 기준은 [상황 지표](references/status-systems.md)를 따른다.

컷 내부 시간은 현실과 1:1로 흐르게 하고 시간 생략은 컷 경계의 `clockTransition`으로 표현한다. 오프닝과 컷 전환 뒤에는 기존 화면을 읽고 현재 상황을 파악할 여유를 둔다. 도입부의 평범한 방송 흐름, 정보 갱신의 간격, 변화와 결말의 구성은 [호흡과 변화](references/direction.md#호흡과-변화)에 맞춰 조율한다.

상태·방송 안내·등급별 문자 알림음과 지역 수신 강조는 엔진 기본 기능을 활용한다. 뉴스는 기본 무음으로 두고 필요한 경우에 소리를 지정한다. 작품 고유 음향은 [음원 제작](references/audio.md)에 따라 합성하거나 출처·사용권을 확인한 로컬 파일로 준비한다. 연속적인 공간 분포는 [그리드 색면](references/format.md#그리드-색면)과 동봉 생성 예제로 작성한다. 합성 자료와 실측 자료의 출처를 구별한다.

## 작품 파일 작성과 검증

영상으로 제작할 때는 [작품 파일과 CLI](references/format.md)에 따라 방송 요소와 연출을 고정된 작품 데이터로 옮긴다. 정확한 필드 계약은 설치된 CLI의 `dbs schema`, 명령은 `dbs --help`로 확인한다. 롤플레잉은 집필에 사용하며 재생·렌더 중 실시간 AI 호출에 의존하지 않는다.

`dbs validate`로 입력을 검사하고 `dbs preview`에서 화면·음향을 재생·탐색한다. 문안 가독성·지도 범위·음향·시점을 수정하며 중요 장면의 앞뒤와 컷 경계를 확인한다. 필요한 `dbs frame`·구간 `dbs render`로 검증한 뒤 전체 영상을 출력한다. 웹 미리보기는 저장한 변경을 현재 위치에서 일시정지해 반영하므로, 매번 전체 영상을 다시 만들 필요는 없다.

내용·시점·공간·기관의 관계와 정보·소리의 전달 경로를 함께 검토한다. 의도된 허구 속 모순을 실수로 없애거나 조사 실수를 의도된 모순으로 취급하지 않는다. 실제 출력에서는 문안의 전문과 핵심 지시가 읽히는지, 변화와 침묵이 의도한 의미로 전달되는지 확인한다.

## 결과물 전달

시나리오·필수 자산·재생성 코드·출처 안내를 전달하고, 이후 수정·재개에 필요한 집필 원본을 보존한다. 임시 출력 검토·통계 파일은 전달 묶음에서 제외한다. 출력 파일의 실제 상태와 미검증 항목을 구분해 보고한다.

영상에는 허구임을 알리는 표기를 포함하고, 출력과 함께 생성한 `.credits.txt`의 출처를 게시 설명에 포함한다. 실제 송출이나 외부 게시·업로드는 별도 요청을 받은 경우에 수행한다.
