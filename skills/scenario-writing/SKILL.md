# 재난방송 호러 작품 작성

## 역할과 작업 위치

이 스킬은 엔진 개발 AI와 별개의 창작 AI가 사용한다. 사용자는 독립된 빈 워크스페이스에 npm 패키지인 CLI를 별도로 설치하고 이 스킬 묶음을 따로 받아 사용한다. 엔진 개발 저장소나 개발용 AGENTS.md는 필요하지 않다.

실제 작품은 사용자가 지정한 창작 워크스페이스에 작성한다. 스킬 배포물 내부에 작품을 저장하거나 엔진 코드에 줄거리·문안을 넣지 않는다. 기술 검증용 데이터와 실제 작품은 구별한다.

## 근거 찾기

[창작 근거 자료](references/README.md)에서 필요한 종류를 선택한다. 모든 자료를 무조건 읽기보다 장면에 필요한 발령 체계·기관·문안을 찾아 원천 근거까지 확인한다.

- [재난문자 운영·발송 기준](references/disaster-sms-rules.md): 사용기관, 시간대, 매체, 직접 발송 권한.
- [표준문안 전문](references/disaster-sms-templates.md): 해당 재난 유형과 행동 단계에 맞는 실제 문장.
- [민방위 경보](references/civil-defense.md): 발령·전달, 사이렌·방송·자막·문자 사이의 차이.
- [기상·지진·홍수·산사태 정보](references/hazard-information.md): 시간·단계·관측값의 의미.
- [뉴스 표현](references/news-writing.md): 발표 주체, 확인된 사실, 후속 갱신의 문체.

공식 문안과 새 창작 문장을 구별한다. 원문 사례나 사용자 예시를 의무적인 플롯으로 삼지 않는다. 자료의 판본보다 과거를 배경으로 하면 해당 시기의 제도를 확인하고, 확인되지 않은 사실을 실제 규정이라고 쓰지 않는다.

## 집필과 연출

1. 사용자가 정한 소재·길이·분위기·매체를 바탕으로 사건의 흐름을 설계한다. 미정인 창작 선택은 작품에 맞춰 결정하되 이미 합의한 조건을 바꾸지 않는다.
2. 사건 내용과 관객이 정보를 보게 되는 시점을 구분한다. 사건 발생·발령·보도·수신 시각이 다르면 그 차이를 명시한다.
3. 문자의 대상·행동·발신자와 뉴스의 발표 주체·확인 범위를 구별한다. 지도에서 강조하는 구역과 문안의 대상 범위를 맞춘다.
4. 내용과 함께 등장·퇴장·지도 이동·강조·음향·침묵·전환의 시점을 작성한다. 컷 내부 시간은 현실과 1:1로 흐르게 하고, 시간 생략은 명시적 컷 경계로 표현한다.
5. 절제된 방송 화면을 기본으로 삼되 모든 작품에 같은 긴장 장치나 반전을 강제하지 않는다. 행정 표현의 현실감과 읽을 시간을 확보한다.

## 엔진을 이용한 확인

데이터 형식과 명령은 설치된 CLI의 공개 도움말과 해당 버전의 배포 문서에서 확인한다. 존재하지 않는 명령이나 미구현 필드를 추측해 사용하지 않는다. 엔진이 아직 실행 가능하지 않으면 실행했다고 보고하지 말고 집필 자료와 필요한 연출 의도를 작성한다.

엔진이 준비되면 작품 데이터 검증 → 주요 프레임·구간 출력 → 문안 가독성·지도 범위·음향·시간 확인 → 전체 출력 순으로 진행한다. 오류는 작품 데이터에서 고칠 수 있는지 먼저 판단하고, 엔진 기능이 부족하면 구체적인 필요한 기능을 개발 작업으로 분리한다. 창작 중 엔진 코드를 임의로 바꾸지 않는다.

## 결과물 확인

- 내용·시점·공간·기관의 관계가 의도와 일치하는지 확인한다. 의도된 허구 속 모순을 실수로 없애거나, 조사 실수를 의도된 모순으로 포장하지 않는다.
- 실제 규정의 문안과 작품에서 새로 작성한 내용이 참고자료에서 뒤섞이지 않게 한다.
- 출력 파일의 실제 상태와 미검증 항목을 구분해 전달한다. 영상에는 허구임을 알리는 표기를 포함하고, 실제 송출이나 외부 게시·업로드는 별도 요청 없이 수행하지 않는다.
