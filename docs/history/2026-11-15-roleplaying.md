# 역할별 반복 롤플레잉 집필

## 판단과 반영

작가 AI가 사건의 전모와 전개를 관리하고, 하위 에이전트가 인물·조직 역할로 제한된 정보에 반응하는 집필 방법을 F6·P4의 창작 스킬에 추가했다. 핵심은 같은 역할들과 상황을 조금씩 진행하며 여러 차례 주고받는 롤플레잉이다. 한 번의 위임으로 역할별 완성 대본을 모으는 방식으로 대체하지 않는다.

`SKILL.md`는 새 작품·상호작용 장면의 집필 단계에서 방법을 안내하고, 상세 절차는 `references/roleplaying.md`에 둔다. 작가가 상황을 갱신하고 역할별로 도달한 정보를 전달한 뒤, 응답의 행동·결과·공개 여부를 확정해 다음 순환으로 연결한다. 역할은 앞선 판단·행동·발언·의문을 기억하며, 에이전트를 재생성하더라도 그 역할이 알게 된 내용만 인계한다. 상위 전체 대화의 상속이나 공유 작품 파일을 통한 정보 유출을 피하도록 입력 범위도 설명했다.

역할의 내부 판단과 공개 발표, 작가가 확정한 사건과 역할의 제안·추측을 구별한다. 같은 시점의 독립 반응과 발표가 도달한 뒤의 후속 반응도 구분해 정보·시간의 인과관계를 유지한다. 중요한 행동·전달 시점이 바뀌면 후속 반응을 다시 진행하고, 최종 결과는 고정된 작품 데이터로 정리한다. 엔진 재생 중 AI 호출은 추가하지 않는다.

작가용 진행 기록·역할별 기억과 대화는 이후 수정·재개에 필요한 집필 원본이다. 작품 폴더에서 필요에 따라 만드는 `src/writing/`에 보존하고 Git 추적하도록 안내한다. 확정된 사건과 대기 중인 보고·질문, 정보 도달 시점을 기록하며 출력 검토용 이미지·영상과 구별한다. CLI 초기화가 자동 생성하는 폴더 구성은 변경하지 않았다.

작은 문안 수정은 반복 진행 대상에서 제외할 수 있으며, 하위 에이전트가 없는 환경에서는 작가가 같은 정보 구분을 관리한다. 배역 수·사건 전개·결말은 고정하지 않았다. 요구사항은 SPEC의 F6, 설계는 TECH의 창작 지원, 현재 상태는 PLAN의 P4에 연결했다.

## 검증 범위

- 스킬 형식 검사를 통과했다. 스킬과 관련 개발 문서의 Markdown 23개 파일에서 로컬 링크·앵커 153개를 확인했고 누락이 없었다.
- 실제 `dbs skill --out`으로 내보낸 22개 파일의 경로 집합·내용이 스킬 정본과 일치했다.
- 독립 집필 평가에서 상위 문맥을 상속하지 않는 지자체·언론사 역할을 생성해 각각 3턴·4턴 진행했다. 신고→공개 안내→현장 확인→후속 보도·질의→지자체 답변→기사 갱신의 입력·응답과 결과 문안을 검토했다. 비공개 보고는 지자체에만 전달했고, 언론은 공개 안내·공보 답변에 따라 보류·보도·추가 취재를 이어 갔다. 마지막에는 주민 행동을 바꿀 새 사실이 없어 추가 문자를 보류했다.
- 실습 중 확인한 텍스트 집필의 종료 범위는 요청한 단계까지만 작성하도록 명시했다. 중요 전개 변경 시의 기억 복원과 `src/writing/` 기록 보존은 지침 검토 범위이며, 별도 재개 실습은 하지 않았다. 평가용 기록·장면은 저장소 밖 임시 폴더에 격리했다.

엔진 구현·작품 형식·공식 규정 자료는 변경하지 않아 전체 테스트·빌드·영상 출력은 수행하지 않았다. 설치된 사용자 스킬·GitHub 원격·npm 배포물은 갱신하지 않았다.
