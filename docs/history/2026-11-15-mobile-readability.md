# 모바일 가로 가독성과 전문 표시

## 표시 기준

모바일 가로 전체화면을 기준으로 핵심 본문을 읽기 쉽게 하고, 각 문안은 전문을 한 번에 보여준다. 문안은 짧게 작성하며 페이지 번호·자동 분할·시간에 따른 본문 교체를 사용하지 않는다. 정정 안내도 일반 수신 문자로 표시하고 본문으로만 전달한다. 별도 정정 배지나 이전 문자 연결을 생성하지 않는다.

## 구현과 계약

- 지도·문자 폭을 60:40으로 배분한다. 재난문자·뉴스 본문 40px, 이전 문자 32px, 채팅 28px을 사용하고 시계·등급·출처·지도 라벨·방송 안내도 함께 키웠다. 상단과 하단 치수는 `src/video/layout.ts`에서 공유한다. 채팅 높이는 260px이다.
- 854×480 가로 축소본에서 핵심 본문은 약 18px에 해당한다. 보조 글자의 대비도 높였다. 실제 휴대폰 기기별 화면·압축·플랫폼 UI 차이까지 측정한 것은 아니다.
- 본문 길이와 개행 분량을 검증한다. 문자에는 발신자 접두사까지 포함하며, 뉴스·방송 안내는 출처 표시명이 넘치는 경우도 거부한다. 정확한 길이 한도는 배포용 `references/format.md`에서 관리한다. 이는 엔진 화면 한도다.
- 페이지 렌더·번호·분할 함수와 `pageSeconds`, 정정 참조 `corrects`를 제거했다. 읽기 시간 경고는 최소 8초·초당 8자 기준으로 유지한다. 창작 안내와 검증 입력도 짧은 전문 표시 기준으로 정리했다.

F3·F7·N1 → TECH의 화면 설계 → PLAN의 P9로 추적한다.

## 검증과 배포

- 전체 테스트 58개 통과. 전문이 처음부터 끝까지 표시되고 시간이 지나거나 역방향 탐색해도 바뀌지 않는지, 정정 배지·페이지 번호가 없는지, 긴 문안·과도한 개행·제거한 필드를 거부하는지 확인했다. 최종 표시명 검증 변경 후 관련 계약·가독성 테스트도 통과했다.
- 타입 검사·빌드·JSON Schema 출력·`git diff --check` 통과.
- 저장소 밖 `/tmp/dbs-mobile-fulltext-fixtures`에 기술 검증 입력을 생성했다. Linux/Chrome Headless Shell/`swangle`에서 일반 문자·채팅·뉴스와 방송 안내의 실제 PNG를 확인했다. [854×480 확인 화면](../screenshots/mobile-landscape.png)과 [전체 화면](../screenshots/chat.png)을 보존한다. 최대 길이 문자·뉴스·채팅도 별도 경계 입력으로 잘리지 않는 것을 확인했다.
- 공개 npm 0.2.0은 변경하지 않았다. 다음 배포에서는 문안 한도와 `pageSeconds`·`corrects` 제거에 따른 계약 변경을 안내한다. 기존 작품은 제거한 필드를 삭제하고 길이 검증에 맞춰 문안을 간결하게 수정한다.
