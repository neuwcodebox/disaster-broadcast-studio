# 선택적 스트리밍 채팅

## 요청과 판단

현황판을 유튜브 같은 플랫폼에서 스트리밍 중이라는 설정에 맞춰 사람들의 반응을 보여주는 채팅을 추가했다. 지도 위에 대화를 겹치면 지역과 안내를 읽기 어려워 오른쪽 문자 패널 아래 260px을 배정하고 약 72% 높이는 문자 이력에 남긴다. 작은 채팅 제목·본문과 좁은 메시지 간격으로 문자보다 낮은 정보 위계를 유지한다. 기존 작품에 강제하지 않고 선택한 구간에만 켠다. 플랫폼 로고나 실제 서비스 연결은 필요하지 않으므로 작성된 대화를 결정적으로 재생한다.

## 구현

- `chat` 구간 이벤트가 패널을 열고 `chat-message` 단발 이벤트가 패널 ID·닉네임·본문·이름 색상을 지정한다. 패널 참조·메시지 수신 구간·동시 패널 충돌을 컴파일 시 검증한다. 메시지의 활성 종료도 패널 종료로 제한한다.
- 패널 아래에 새 메시지를 추가하고 이전 대화를 위로 밀어낸다. 짧은 진입 효과는 콘텐츠 프레임으로 계산하며 최근 12개만 DOM에 올린다. `stateAt`과 CLI `inspect`는 해당 패널의 전체 수신 대화를 보존한다.
- 컷을 넘는 패널은 기존 `carry` 규칙을 따르고 시간 도약 동안에는 다른 방송 정보와 함께 대화·수신 효과를 유지한다. 새 패널은 빈 대화로 시작한다. 방송 안내·전체 화면 효과·송출 종료는 채팅에도 적용한다.
- 기본 채팅 알림음은 없으며 닉네임·문구·메시지 간격은 작품에서 작성한다. 창작 안내에는 같은 사람의 재등장과 질문·목격담·의심 등 관점 차이를 활용하고 공식 정보와 구별하는 조언을 추가했다.

F7 → TECH의 스트리밍 채팅 → PLAN의 P8로 추적한다. 정확한 필드 계약과 YAML 예시는 배포용 `references/format.md`에서 관리한다.

## 검증

- `npm test`: 57개 통과. 채팅의 선택성·패널 구간·동시 메시지 순서·컷 이월·시계 전환 정지·역방향 탐색·전체 대화 보존·참조/구간 오류·중첩 거부·입력 길이와 HTML 이스케이프를 포함한다.
- `npm run typecheck`, `npm run build`, `git diff --check` 통과.
- `scripts/render-fixtures.mjs /tmp/dbs-chat-fixtures`로 실제 작품이 아닌 기술 검증 입력을 저장소 밖에 생성했다. 기존 검증 입력은 유지하고 `chat.json`을 추가했다.
- Linux/Chrome Headless Shell/`swangle`에서 720번 프레임을 PNG로 출력해 지도·문자·채팅·뉴스를 함께 확인했다. [확인 화면](../screenshots/chat.png)은 260px 채팅과 문자 3건이 함께 보이는 배치다. 960번 프레임에서는 최대 160자 본문 전체가 최신 항목으로 읽히는 것을 확인했다. 배치 조정 후 채팅·문자 이력 테스트와 빌드도 통과했다.
- 654~689번의 36프레임 MP4와 등장 중간 프레임을 확인했다. H.264, 1920×1080, 60fps, AAC 트랙을 `ffprobe`로 확인했다. 새 메시지가 나타나며 이전 대화를 위로 밀어내고 지도·문자·뉴스와 겹치지 않았다. 임시 출력은 `/tmp/dbs-chat-fixtures`에 두었다.
