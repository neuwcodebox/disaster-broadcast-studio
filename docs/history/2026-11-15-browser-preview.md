# 웹 실시간 미리보기

## 목적과 선택

영상 파일을 출력하기 전에 화면·음향을 재생하고 시나리오 수정 결과를 바로 확인하도록 F5를 확장하고 P7로 추적한다. `dbs preview <scenario> [--port <번호>]`는 루프백 HTTP 주소를 출력한다. 기존 `Broadcast`와 버전이 같은 Remotion Player를 사용하고 자산·방송 props 준비를 PNG/MP4와 공유한다. 별도 편집기나 영상 인코딩은 추가하지 않았다.

재생·일시정지·탐색 막대·음량·전체 화면과 프레임·컷 이동을 제공한다. 시나리오 내용 및 현재 문서에 선언된 지도·음원의 변경을 감지한다. 정상 갱신은 현재 위치에서 일시정지하고 길이가 줄면 마지막 프레임으로 제한한다. 입력 오류는 마지막 정상 화면·음원을 유지하며 수정 후 자동 복구한다. 누락 음원 생성과 손상 지도 수정도 문서를 다시 저장하지 않고 감지한다. 변경된 음원은 새로운 URL로 제공하며 종료 시 임시 번들·자산을 정리한다. 원본 작품 폴더 전체를 HTTP로 공개하지 않고 준비된 자산과 오디오 Range 요청만 제공한다.

## 지도와 재생

영상 출력은 프레임마다 MapLibre의 idle을 기다리고 캔버스를 캡처한다. 이 경로를 그대로 사용한 초기 웹 재생에서는 카메라 이동이 매우 느려졌다. 웹 미리보기는 같은 MapLibre 지도와 SVG 강조를 사용하면서 캔버스를 직접 표시하고, 카메라 변환 직후 SVG를 투영한다. 초기 지도·글꼴은 Player 버퍼 대기로 준비하며 이동 중에는 매 프레임 idle·캔버스 읽기를 피한다. PNG/MP4의 결정적 캡처 경로는 유지한다. 재생 성능과 파일 출력의 60fps 규격은 구분한다.

## 검증 범위

- Node.js 24·Linux·Chromium 소프트웨어 WebGL에서 방송·문자·뉴스, 프레임 탐색, 저장 후 위치 유지·일시정지, 문법 오류 표시와 복구를 확인했다.
- 실제 수신음 파일의 브라우저 `playing` 이벤트, 보조 지도·카메라 이동 구간을 지나가는 재생, 카메라 이동 중 PNG 출력을 확인했다. 브라우저 콘솔 오류는 없었으며 기존 지도 메시 크기 경고는 남는다. GPU별 실시간 60fps나 Safari·Windows/macOS 실행은 확인하지 않았다.
- 빠른 전체 테스트 50개, 타입 검사와 빌드가 통과했다. 미리보기 테스트는 유효 입력 갱신, 오류 중 정상 상태 보존, 누락 음원·손상 지도·삭제한 시나리오 복구, 음원 변경, 공개 파일 범위와 HTTP Range/HEAD 계약을 확인한다. 고정 대기 시간에 의존하지 않는다.
- 로컬 `npm pack`을 별도 `/tmp` 폴더에 오프라인 설치해 번들 생성·HTTP 페이지·방송 props·음원 Range 응답·서버 종료를 확인했다. 공개 npm 배포는 수행하지 않았다.

사용법은 README·작품 작업공간 템플릿·창작 스킬의 제작 흐름과 CLI 계약에 반영했다. 요구사항과 설계는 SPEC F5·TECH에 유지한다.
