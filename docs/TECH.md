# 재난방송실 — 기술 설계

## 전체 구조

<!-- 구성요소의 책임·소유 상태와 연결·데이터 흐름을 설명한다. -->

작품 파일과 로컬 자산 → 파싱·검증 → 정규화된 타임라인 → 프레임별 상태 계산 → 방송 화면·음향 → 이미지 또는 영상 출력으로 연결한다. 렌더러는 작품의 이야기를 결정하지 않는다.

### 작품 입력과 검증

- **책임·소유 상태:** 엔진 워크스페이스 밖의 작품 디렉터리가 내용·연출·자산 참조를 소유한다. CLI는 명시적으로 전달받은 작품 경로를 읽고 상대 자산 경로는 해당 작품을 기준으로 해석한다. 입력 계층은 문법·참조·시간의 유효성을 검사한다.
- **구현 방식:** YAML을 우선 검토하고 TypeScript의 공통 스키마로 검증한다. 최종 포맷은 P1에서 정한다. 검증된 데이터는 출력용 중간 표현으로 한 번 정규화한다.
- **관련 요구:** F1, F6, N3

### 창작 AI 지원 산출물

- **책임·소유 상태:** 엔진 개발 워크스페이스는 배포할 창작 스킬과 참고자료를 관리하고 실제 작품 데이터는 소유하지 않는다.
- **구현 방식:** 배포용 정본은 `skills/scenario-writing/SKILL.md`와 같은 디렉터리의 `references/`에 둔다. 자동 로딩용 `.agents/skills/`에는 등록하지 않는다. 스킬은 작품 작성·검증·부분 확인·출력을 안내하고 동봉 자료만 상대 경로로 참조한다. 참고자료를 개발용 폴더에 복제하지 않는다. 창작 AI는 별도로 받은 스킬을 사용하며 개발 AGENTS.md와 개발 저장소 내부 파일에 의존하지 않는다.
- **관련 요구:** F1, F5, F6, N3, N4

### 프레임 상태 계산

- **책임·소유 상태:** 현재 영상 프레임에 대응하는 컷·이야기 시각·누적 사건·연출 상태를 계산한다. 화면 컴포넌트가 사건 상태를 따로 축적하지 않는다.
- **구현 방식:** 정규화 데이터와 프레임 번호의 함수로 구성한다. 음향과 지도도 동일 시간축을 사용한다. 실시간 타이머로 상태를 진행시키지 않는다.
- **관련 요구:** F2, F4, N2

### 방송 화면과 지도

- **책임·소유 상태:** 전달받은 상태를 지도·문자 이력·뉴스·시계로 표현한다. 지도 런타임은 화면 자산의 로딩 상태만 소유하며 작품 시간과 분리한다.
- **구현 방식:** Remotion/React 화면에 MapLibre 지도를 통합하고 deck.gl의 지리 레이어를 필요한 범위에 사용한다. 기존 disaster-feed-web의 행정구역·보조 지도 구현을 검토해 재사용 가능한 표현을 이식한다. 운영 API와 실시간 로직은 가져오지 않는다.
- **관련 요구:** F3, F4, N1, N2

### 출력 진입점

- **책임·소유 상태:** 작품 선택, 검증 결과, 출력 범위·파일 경로와 실행 결과를 관리한다.
- **구현 방식:** Remotion의 프레임·영상 렌더링을 사용한다. 별도 영상 엔진이나 GUI 편집기를 만들지 않는다. 아직 구현되지 않은 명령 이름은 사용 계약으로 공개하지 않는다.
- **관련 요구:** F5, N3

## 주요 경계와 계약

<!-- 외부 연동과 모듈 사이에서 유지해야 할 입출력·상태·실패 계약을 설명한다. -->

### 작품 데이터 → 타임라인

- **관련 요구:** F1, F2, F4, N2
- **입력·출력:** 작품 메타데이터·기관·지역·사건·컷·연출 트랙·자산 참조를 받아 프레임 단위 중간 표현을 만든다. 사건은 안정된 ID로 서로 참조한다. 내용 필드와 연출 필드는 구분하되 같은 작품에서 함께 작성한다.
- **상태와 권한:** 사건 내용은 원본 그대로 보존한다. 정정은 원 사건을 삭제하는 갱신이 아니라 별도 사건과 참조 관계로 나타낸다. 시간 단위 변환과 프레임 반올림은 파서 경계에서 한 규칙으로 처리한다.
- **실패 시 동작:** 파일·항목·필드 경로와 이유를 반환한다. 중복 ID, 잘못된 시간, 누락 자산, 모호한 동일 속성의 동시 제어를 검출한다. 기관 간 주장 불일치는 창작 내용이므로 허용한다. 최종 스키마와 동시 제어 우선순위는 P1에서 확정한다.

### 컷 → 프레임 상태

- **관련 요구:** F2, F4, F5, N2
- **입력·출력:** 컷의 영상 시작 프레임·길이·이야기 시작 시각을 받아 컷 내부 경과를 1:1로 더한다. 컷 경계에는 시각 점프와 화면·음향 전환을 명시한다.
- **상태와 권한:** 누적 문자·지도 강조처럼 지속되는 상태는 이전 사건을 프레임 기준으로 평가해 복원한다. 다음 컷으로 유지할 항목과 종료할 항목을 데이터로 표현한다. 프레임을 순차 재생해야만 정답이 나오는 구조를 쓰지 않는다.
- **실패 시 동작:** 컷의 겹침·공백·지원하지 않는 배속을 검증한다. 의도한 무음·검은 화면도 길이가 있는 연출로 표현하여 시간 공백과 혼동하지 않는다.

### 지도·자산 → 캡처

- **관련 요구:** F3, F5, N2, N4
- **입력·출력:** 고정된 경계·타일·폰트·음향과 카메라 상태를 로드하고 준비된 프레임을 캡처한다. 자산 목록에는 출처·사용권·버전 또는 해시를 둔다.
- **상태와 권한:** 지도 카메라는 프레임으로 계산해 `jumpTo` 등 즉시 적용 방식으로 설정한다. 실시간 지도 애니메이션 대신 프레임 보간을 사용한다. 로딩 완료 전 캡처를 보류한다.
- **실패 시 동작:** 필수 자산 누락·타일 로딩 실패는 빈 지도나 대체 글꼴을 조용히 출력하지 않고 실패시킨다. 준비 대기에는 제한을 두고 원인을 반환한다.

## 기술 선택과 중요한 결정

<!-- 바꾸기 어려운 선택의 이유·대안·제약과 관련 요구사항을 기록한다. -->

### Remotion + React + TypeScript

- **선택:** 텍스트 데이터 기반 화면·음향 구성과 영상 출력의 공통 기반으로 사용한다.
- **이유·대안:** 웹 기반 화면 재사용과 프레임 지정 출력이 가능하다. 직접 FFmpeg 필터로 화면 전체를 작성하거나 영상 엔진을 만드는 것보다 한글 레이아웃과 지도 연동이 용이하다.
- **상태·근거:** 채택 방향 합의. 정확한 버전은 P1에서 고정한다. [CLI render](https://www.remotion.dev/docs/cli/render)는 props 및 출력 옵션을 지원한다. [라이선스](https://www.remotion.dev/pricing)는 개인·작은 조직의 무료 조건과 조직 규모별 조건이 다르므로 실제 사용 주체 기준으로 확인한다.
- **관련 요구:** F1, F4, F5, N3, N4

### MapLibre GL JS + deck.gl

- **선택:** MapLibre의 지도·카메라와 필요한 deck.gl 레이어를 사용한다. 남한 행정구역을 기본 단위로 하고 terrain은 이야기 가독성에 도움이 될 때 선택적으로 사용한다.
- **이유·대안:** 기존 프로젝트 경험과 지리 데이터 표현을 활용한다. 기본 방송 화면에 3D 지형과 다수 레이어를 무조건 넣지 않는다.
- **상태·근거:** 채택 방향 합의. [Remotion 지도 통합](https://www.remotion.dev/docs/maps)은 `delayRender`/`continueRender`, 지도 준비·캡처 및 WebGL 설정을 설명한다. [기존 지도 구현](https://github.com/neuwcodebox/disaster-feed-web/blob/main/src/components/disaster-map/DisasterMap.tsx)은 재사용 후보이며 해당 서비스의 운영 의존성은 제외한다.
- **관련 요구:** F3, N1, N2, N3

### 절제된 단일 방송 화면

- **선택:** 상단에 제목·시계, 본문 왼쪽 약 65% 지도와 오른쪽 약 35% 문자 이력, 하단 뉴스 영역을 시작점으로 잡는다. 비율은 한글 문안 검증에 따라 조정한다.
- **이유·대안:** 지도에서 위치를, 문자에서 지시를, 뉴스에서 별도 정보원의 해석을 읽게 한다. 검은색에 가까운 배경·회색 구분선·밝은 본문을 기본으로 하며 경보 색은 필요한 지역과 상태에 제한한다.
- **상태·근거:** 합의한 시각 방향. 글꼴 크기·행수·표시 시간은 P2의 실제 1080p 프레임에서 정한다. 긴 문안은 전문을 보존하고 표시 유지·페이지 또는 이력 이동 규칙으로 처리한다. 내용 축약으로 임의 해결하지 않는다.
- **관련 요구:** F3, F4, N1

### 로컬 자산 고정

- **선택:** 지도·폰트·음향을 허용된 로컬 자산으로 고정하고 렌더 시 외부 수집을 하지 않는다.
- **이유·대안:** 웹 타일의 변동·접속 실패를 완성 영상에서 배제한다. 지도 라이브러리 라이선스와 지도 데이터 사용권은 별개다.
- **상태·근거:** 원칙 채택, 자산 선정은 P1. [OSM 타일 정책](https://operations.osmfoundation.org/policies/tiles/)은 기본 타일 서버의 대량 저장을 허용하지 않는다. 자체 허가된 타일이나 [PMTiles](https://docs.protomaps.com/pmtiles/maplibre) 등 배포 방식을 검토한다. 기존 프로젝트의 경계 데이터·CARTO 스타일을 자동으로 영상 재배포 가능하다고 간주하지 않는다.
- **관련 요구:** F3, F5, N2, N4

## 실행 환경

<!-- 지원 플랫폼과 런타임, 의존성 및 실행 조건을 설명한다. -->

로컬 Node.js/Chromium 기반 환경을 목표로 한다. 대상 OS·Node.js·패키지 버전·GPU와 글꼴은 P1에서 확인하여 고정한다. 60fps는 출력 기준이지 실시간 렌더 속도 보장이 아니다. [GPU 안내](https://www.remotion.dev/docs/gpu)를 참고해 WebGL 가속과 동시 렌더 수를 조정하되 그래픽 하드웨어를 미확인 상태에서 필수 구매 조건으로 만들지 않는다. 관련 요구: F5, N2, N3.

## 배포

<!-- 설치·설정·배포·이전과 복구 과정을 설명한다. -->

엔진·CLI는 npm 패키지로 배포하고 `skills/scenario-writing/` 전체는 별도의 스킬 묶음으로 배포한다. npm 패키지명과 실행명은 아직 미정이다. 사용자는 독립된 빈 워크스페이스에서 CLI를 설치하고 스킬 묶음을 별도로 받아 사용한다. 스킬 배포물에는 SKILL.md와 references의 정본이 함께 들어가며 개발 저장소 루트로 올라가는 링크가 없어야 한다. 개발 저장소·외부 작품·출력물을 분리하고 완성 출력에는 작품 식별자와 입력·자산 버전을 연결할 수 있게 한다. 사용 중인 작품을 덮어쓰는 대신 명시적 출력 경로로 저장한다. npm 패키지명·설치 및 실행 명령은 구현 후 CLI 배포 안내에 제공하고 스킬은 그 공개 계약을 안내한다. 현재 존재하지 않는 명령·설치 절차는 만들지 않는다. 관련 요구: F5, F6, N3, N4.

## 유지보수

<!-- 업데이트·호환성 및 외부 의존성 변경에 대응하는 방식을 설명한다. -->

실제 작품이 생긴 뒤 스키마를 변경할 때 영향받는 작품과 변환 필요성을 확인한다. 아직 사용하지 않은 가상 버전의 호환 계층은 만들지 않는다. Remotion·지도·폰트 업데이트는 프레임 및 음향 출력의 회귀를 확인한다. 공식 문안은 시대별 자료로 구분해 보관하고 개정 시 과거 작품을 자동 수정하지 않는다. 관련 요구: F1, F6, N2, N3.

## 검증 접근

<!-- 수용 기준 중 검증할 계약·위험과 필요한 환경을 설명한다. -->

### 시간·입력 계약

- **관련 요구:** F1, F2, F4, F5, N2
- **확인 방법:** 고정 프레임의 사건 상태, 컷 경계, 참조 오류, 동시 연출 충돌과 임의 위치 탐색을 빠른 결정적 테스트로 확인한다.
- **필요 환경:** 로컬 단위 테스트 환경. 전체 영상 렌더 없이 먼저 검증한다.

### 방송 화면과 완성 출력

- **관련 요구:** F3, F4, F5, N1, N2, N3, N4
- **확인 방법:** 한글 장문·다수 사건·지도 로딩·음향 경계가 포함된 프레임과 짧은 구간을 확인한 뒤 전체 출력의 해상도·fps·음향·길이를 검사한다. 정지 화면 검사만으로 영상 완성을 판정하지 않는다.
- **필요 환경:** 실제 대상 OS/GPU, 고정 의존성·자산, 미디어 검사 도구와 플레이어.

### 자료 근거

- **관련 요구:** F6, N4
- **확인 방법:** 공식 원문·인용·요약·창작 예시의 구분, 판본 연결, 자료·자산 사용조건을 대조한다.
- **필요 환경:** 공식 자료 열람 및 로컬 보존본.

### 독립 배포 사용

- **관련 요구:** F5, F6, N3
- **확인 방법:** 개발 저장소가 보이지 않는 빈 워크스페이스에 CLI와 스킬을 각각 받아 외부 작품 검증·부분 출력·전체 출력을 수행한다. 스킬의 모든 로컬 링크가 동봉 파일로 해소되는지 확인한다.
- **필요 환경:** 개발 저장소와 분리된 임시 워크스페이스, 배포용 CLI와 스킬 묶음.

미확정 스키마·그래픽 환경·자산 조건은 PLAN의 P1, 작품 시대에 맞는 자료 적용과 자산 권리는 P4에서 확인한다.
